**Design note (not a separate task, but worth recording)**: `Ordered Match + Classify` runs once per RFQ but outputs one item *per product* (matching the original filter chain's shape). Downstream, `Create folder` must run exactly once *per RFQ*, not once per product — and `update_workflow`'s available operations don't expose the `executeOnce` node setting, so a `Merge Match Results into RFQ` node was added to collapse the per-product items back into a single item (`{ rfq: { ...rfq, products: [...with match evidence attached] } }`) before the duplicate check and `Create folder`. This also fixes a pre-existing latent bug: the original chain had no such collapse either, so a multi-product RFQ could plausibly have created multiple Drive folders even before this change — undocumented in `.codex/baselines`, found during this implementation.
